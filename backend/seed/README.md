# Synthetic Pakistan fixture generator — audit before writing

Run without Firebase, credentials, network, or writes:

```sh
node backend/seed/seed.js --dry-run
node --test backend/seed/test/*.test.js
```

`node seed.js` also defaults to dry-run. An actual operator-approved write requires
`--write` (or `npm run seed` in this directory) and the operator's own configured
Application Default Credentials. Do not put credentials in this repository/chat.
No live seed is performed by validation or CI.

The audited default contains 49 synthetic worker profiles/cities including named
Attock locations, all five ranks at 156-completion/year steps, and at least 100
reviews per worker. Every worker gets every language **in the configured review
corpus**, then a weighted mixture. Random sampling alone previously left 20/49
workers missing a corpus language. A small REVIEWS_PER_WORKER override is now
clamped to 100, not allowed to silently defeat that requirement.

Current bundled review corpus: ur, en, pa, ps, sd, bal, skr, hnd, hi, ar, fa, bn.
This is **not an exhaustive claim about every language/dialect spoken in
Pakistan**, nor a claim that native-language review text has been professionally
verified or generated by a live ML service. The application language catalog is
separate/dynamic; catalog availability is not a translation-quality guarantee.
Balochi uses ISO `bal`; `brh` is the distinct Brahui language, not an alias. Metadata
reference: https://github.com/unicode-org/cldr-json/blob/main/cldr-json/cldr-localenames-full/main/en/languages.json
Review/migrate any legacy Balochi-labelled `brh` data manually; do not overwrite
legitimate Brahui records or silently change a user's language preference.

## Extend native-language coverage with reviewed data, not app code

Set `SEED_REVIEW_CORPUS=/path/to/reviewed-corpus.json`. The file is an array:

```json
[
  {
    "code": "language-code",
    "nativeName": "Reviewed native name",
    "englishName": "English display name",
    "templates": [
      ["Reviewed native positive text", "English reference text", "pos"],
      ["Reviewed native neutral text", "English reference text", "neu"],
      ["Reviewed native negative text", "English reference text", "neg"]
    ]
  }
]
```

Only supply authentic/authorized language examples. All three sentiment groups are
required. New codes extend fixture/catalog data automatically; no fixed app-language
list or fake substitution of Urdu/English for an unsupported language is added.
Run the audit and inspect its coverage/failures before any live operation.

## Safety and cost limits

- `CLEAN=1 --write` is rejected **before** Firebase initializes. The former unscoped
  collection-delete loop could erase real users/jobs/reviews; it is not a safe
  migration. Use a separately reviewed, scoped operator migration instead.
- Default data estimates about 24,319 document writes (inspect the actual audit).
  This can exceed a free-tier daily write quota. Dry-run is not a billing estimate
  guarantee and does not imply the live project can accept the whole fixture.
- Profiles, locations and reviews are synthetic; do not present them as real
  service providers, genuine testimonials or verified professional addresses.
- No Auth passwords/accounts, actual payment gateway, production credentials,
  quote feature activation or background tracking is provisioned here.
